# Examples

Rutile ships three Rails 8 apps in [examples/](../../examples). Each is an ordinary Rails app: it boots, and its tests pass, on Rails. Each also compiles with `rutile build`, and its integration tests pass against the Rust binary under `rutile verify`. Together they are Rutile's end-to-end test.

| App | Kind | Integration tests | Generated crate |
|---|---|---:|---|
| [blog](../../examples/blog) | JSON API, the proof of concept | 17 | `RustOnRails/examples/blog` |
| [tracker](../../examples/tracker) | JSON API written for Rails, not for Rutile | 24 | `RustOnRails/examples/tracker` |
| [store](../../examples/store) | JSON API and HTML pages, grown one milestone at a time | 33 | `RustOnRails/examples/store` |

## How they're verified

From the Rutile checkout, with RustOnRails beside it (or `RUSTONRAILS_DIR` set):

```bash
bundle exec rake example:check  EXAMPLE=store   # rutile check: no problems
bundle exec rake example:build  EXAMPLE=store   # writes RustOnRails/examples/store
bundle exec rake example:verify EXAMPLE=store   # the integration tests on the binary
bundle exec rake example:test   EXAMPLE=store   # the app's whole suite on Rails
```

`EXAMPLE` is `blog` by default. The tasks start a throwaway Postgres and Redis under `tmp/` first; [Getting Started](Getting-Started.md#the-example-apps) lists every task. `example:verify` runs only `test/integration`, since those tests go through HTTP and can be forwarded to the binary. Model tests run in-process on Rails.

The generated crates are members of RustOnRails' Cargo workspace, beside its `tools/loadgen`. Each is regenerated by `example:build`: `src/` is rewritten whole, and `Cargo.toml` stays as it is. `rake example:benchmark` measures an app on Rails and on Rust after checking that every benchmarked endpoint gives the same status and the same bytes from both; see [Benchmarks](Benchmarks.md).

## blog

The proof of concept: users, posts and comments. It was ported to Rust by hand first; the generated crate replaced the hand port and still passes the Rust tests written for it, in `RustOnRails/examples/blog/tests`.

It exercises:

- `belongs_to`, `has_many` with `dependent: :destroy`;
- an enum with `validate: true`, and scopes, one inherited from `ApplicationRecord` with a parameter;
- validations: presence, length, uniqueness, format with `URI::MailTo::EMAIL_REGEXP`, and a `validate` method;
- callbacks: `before_save ... if: :published?`, `after_create`, and a `before_validation` block;
- `||=` on an attribute and `&.` on an association;
- controllers with `before_action`, strong parameters, `render json:` with a status, and `rescue_from ActiveRecord::RecordNotFound`;
- nested resources, and a route with a lambda constraint that falls through to the next route when it fails.

Its 17 integration tests are in `test/integration`; its 13 model tests run on Rails only. One assertion reads `controller.action_name`, a Rails internal, and is skipped when `RUTILE_TARGET` is set.

```ruby
# examples/blog/app/controllers/posts_controller.rb
def update
  if @post.update(post_params)
    render json: @post
  else
    render json: @post.errors, status: :unprocessable_content
  end
end
```

becomes

```rust
// app/controllers/posts_controller.rb:22
pub fn update(&mut self, req: &mut Request) -> Result<Response> {
    let post = self.post.ok_or(Error::Nil { what: "update" })?;
    let attributes = self.post_params(req)?;
    req.ctx.assign(post, &attributes)?;
    if req.ctx.save(post)? {
        Ok(Response::json(
            status::OK,
            AsJson::<Post>::new().render_option(&mut req.ctx, self.post)?,
        ))
    } else {
        Ok(Response::json(
            status::UNPROCESSABLE_CONTENT,
            errors_json(
                req.ctx
                    .errors(self.post.ok_or(Error::Nil { what: "errors" })?),
            ),
        ))
    }
}
```

`@post` is set by a filter and may be nil, so it's an `Option`, and calling a method on nil is the error Ruby raises.

## tracker

A project and task tracker written as an ordinary Rails 8 API, without Rutile in mind, then compiled without changes to its `app/`. [docs/gaps.md](../gaps.md) records what that took: `rutile check` first reported 28 problems, and five rounds of work closed them.

It exercises:

- token auth in `ApplicationController`: a `before_action` that reads `request.headers["X-Api-Token"]` and halts with `head :unauthorized`, and a private `attr_reader :current_user`;
- `has_secure_token`, `normalizes`, `has_many :through` with `source:`, `class_name:` and `foreign_key:`, and `dependent: :nullify`;
- several enums, numericality with `only_integer` and `allow_nil`, and uniqueness scoped to another column;
- SQL-string scopes (`where("title ILIKE ?", ...)` with `sanitize_sql_like`), `where.not`, and a `date` column compared with `Date.current`;
- model methods such as `overdue?` and `archive!`;
- member routes, shallow nesting, pagination, and `create!`/`update!` with `rescue_from ActiveRecord::RecordInvalid`.

All 24 integration tests pass on the binary.

## store

The example that grows with each milestone of the [roadmap](../roadmap.md). Its tests are grouped by what each milestone added:

| Test file | Tests | What it covers |
|---|---:|---|
| `products_api_test.rb` | 6 | Methods with rbs-inline signatures (`#: (Integer) -> Integer`), optional parameters, validations |
| `orders_api_test.rb` | 3 | Keyword parameters, `normalizes`, creating through an association |
| `everyday_ruby_test.rb` | 8 | Aggregates in Rails' SQL, `select`/`map`/`sum`/`reject` blocks, `find_each` batches, `transaction` with rollback |
| `value_fallback_test.rb` | 3 | Params of any class, and methods that return an Integer or a String, through [Value](Value-Fallback.md) |
| `session_test.rb` | 4 | A cart in Rails' session cookie, plain cookies, `reset_session`, and a cookie passed from Rails to the binary and back |
| `jobs_test.rb` | 2 | `RestockJob` on Sidekiq: a job the binary enqueues run by Sidekiq's Ruby worker, and one Rails enqueues run by the binary's `work --once` |
| `storefront_test.rb` | 7 | ERB pages in a layout, asserting Rails' exact bytes: `link_to`, `content_for`, a `_path` helper, escaping, 404s, and formats other than HTML |

The store falls back to `Value` on purpose in three places: `ProductsController#double` doubles whatever the client sent (`21` is `42`, `"ab"` is `"abab"`), `Product#availability` returns an Integer or a String, and `Product#tag_with` is typed `(untyped) -> untyped`.

`app/helpers/storefront_helper.rb` defines a helper that no template calls. It's there so introspection has an app helper to find; a template that called it would be refused, since Rails would run the app's method rather than one Rutile compiles.

## Adding to them

A change to Rutile that affects generated code shows up as a diff in `RustOnRails/examples/*/src` after `rake example:build`. Rutile's own tests (`bundle exec rake test`) introspect all three apps and translate them.
